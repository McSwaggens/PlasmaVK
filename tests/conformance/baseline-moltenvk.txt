# Conformance tests that pass on MoltenVK 1.4.2 (Homebrew molten-vk, through
# the Homebrew Vulkan loader). `make conformance-mvk` fails when one of these
# stops passing, which keeps the suite itself honest against a second driver.
#
# Not listed: MoltenVK's known deviations from the spec (README.md, "Known
# deviations"), which fail there by MoltenVK's behaviour, not the test's:
#   devsandqueues.host_image_copy_layouts            layout counts not written
#   extensions.device_extension_needs_instance_extension
#                                                    lists VK_KHR_swapchain etc.
#                                                    without VK_KHR_surface enabled
#   queries.copy_results_same_commands               copies 0 for timestamps written
#   queries.copy_results_wait                        earlier in the command buffer
#                                                    (intermittent)
#   synchronization.event_device_state               vkCmdSetEvent / vkCmdResetEvent
#                                                    in one command buffer not ordered
#                                                    by a pipeline barrier
#   privatedata.private_data_slot_destroy_null       crashes on VK_NULL_HANDLE
#   privatedata.private_data_new_objects             a new object at a destroyed one's
#                                                    address reads its private data
#   drawing.primitive_restart                        with primitive restart off, 0xFFFF
#                                                    still restarts a strip
#   dispatch.dispatch_indirect_after_base            vkCmdDispatchIndirect keeps an
#                                                    earlier vkCmdDispatchBase's base
#   debugging.debug_utils_messenger_allocator        the loader frees, through the
#                                                    messenger's pfnFree, memory it
#                                                    did not allocate with it
#   debugging.debug_utils_object_name_messenger      naming a VkDebugUtilsMessengerEXT
#                                                    crashes in MoltenVK (given the
#                                                    loader's handle)
